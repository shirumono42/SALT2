# 名刺管理アプリケーション

営業担当者の名刺入力・整理の手間を減らす、1組織（シングルテナント）向けのWebアプリです。PCブラウザでの利用を想定しています。
フロー: 名刺画像の取り込み → Claudeによる読み取り → 確認・修正 → 登録 → 一覧・検索・詳細表示。

## 使用技術
- Python 3.12+（開発確認は 3.14）/ FastAPI / Jinja2（サーバー側描画）/ SQLite（標準ライブラリ）
- AIモデル: Anthropic Claude（既定 `claude-fable-5-1`、`.env` の `CLAUDE_MODEL` で変更可）。名刺画像を直接モデルに渡し、tool use でJSONスキーマを強制して8項目を抽出します（OCR併用なし）。
- 対応画像形式: **JPEG / PNG / HEIC(HEIF)**。1枚10MBまで（`MAX_UPLOAD_MB`）。HEICはサーバーでJPEGに変換し、EXIFの向きを補正、長辺1568px以下に縮小して保存・送信します。
- 保存: SQLite（`data/app.db`）＋ローカルディスク（`data/images/`）。外部サービスやDockerは不要で、clone後すぐ動かせるためこの構成にしました。画像は静的公開せず、権限チェック付きのエンドポイントからのみ配信します。

## 環境の立ち上げ
前提: macOS/Linux、Python 3.12以上、インターネット接続（Claude API）。

```bash
git clone <このリポジトリ> && cd <ディレクトリ>
./start.sh          # 初回は .venv 作成・依存導入・.env 雛形コピーまで行い終了します
# .env を編集（下記）
./start.sh          # http://127.0.0.1:8000 で起動
```

`.env` の設定項目（`.env.example` 参照。`.env` はコミットしません）:

| 変数 | 必須 | 内容 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 必須 | ClaudeのAPIキー。サーバー側でのみ使用し、ブラウザには出しません |
| `SECRET_KEY` | 必須 | セッション署名用の長いランダム文字列 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 必須 | 初期adminの認証情報（下記） |
| `CLAUDE_MODEL` | 任意 | 利用モデルID |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASSWORD` `SMTP_FROM` | 任意 | 招待メール送信用。未設定ならコードを画面に表示します |
| `MAX_UPLOAD_MB` `DATA_DIR` | 任意 | 上限サイズ(既定10) / 保存先(既定 `./data`) |

## 初期admin・確認用アカウント
- 起動時に、`ADMIN_EMAIL` のユーザーが存在しなければ、`ADMIN_PASSWORD` で **admin** を自動作成します（初回のみ。既存ならパスワードは変更しません）。
- このアカウントを **確認用アカウント** として兼用します。評価者には環境変数を別途共有してください（認証情報はリポジトリに含めません）。
- adminは1名のみで、昇格・削除・無効化の機能はありません（要件外のため）。

## 利用者（user）の追加
1. adminでログイン →「利用者・閲覧許可」画面でメールアドレスを入力して追加（role は常に `user`）。
2. システムが6桁の数字コードを発行し、招待メールで送信します。**SMTP未設定または送信失敗時は、コードを画面に1回表示（サーバーログにも出力）するので、手渡ししてください。**
3. 利用者が `/activate` でメール・コード・新パスワード（8文字以上）を入力して有効化 → 以降はメール+パスワードでログイン。
- コードは1回使用で無効化。5回失敗でコード失効（adminが「再発行」）。有効期限は設けていません。
- 登録済みのメールは追加できません（「登録済みです」）。未登録・未有効化のメールではログインできません。

## role・閲覧許可
| role | 閲覧できる範囲 |
|---|---|
| admin | すべての名刺 |
| user | 自分が登録した名刺 ＋ adminが付与した許可の範囲 |

許可は「利用者・閲覧許可」→ 各利用者の「閲覧許可」画面で、**企業 / 部署 / 人物** 単位に付与・解除します（admin のみ。候補は登録済み名刺から選択、またはキーワード検索）。いずれか1つを満たせば閲覧可能で、許可を解除しても自分の登録分や他の許可は残ります。権限は一覧・検索・件数・詳細・画像取得・編集・削除のすべてに適用され、ID直指定でも権限外は404です。

### 識別方法（同名・同姓同名への対応）
- **企業**: 会社名を正規化（全角半角・大小文字・空白・「株式会社/(株)/Co., Ltd.」等の法人格を除去）したキー。
- **部署**: 企業キー＋部署キーの**組**で一致した場合のみ。別企業の同名部署には広がりません。
- **人物**: 正規化したメールアドレスで識別。同姓同名でもメールが違えば別人。メール未記載の名刺は人物許可の対象になりません。
- キーが空（会社名・部署名・メールが空欄/不正）の名刺は、その種類の許可に絶対に一致しません（安全側）。

## 主な仕様と判断
- 氏名のみ必須。読み取れなかった項目は空欄のまま登録でき、確認画面に**空欄項目の警告を必ず表示**します。AIの推測補完はプロンプトで禁止しています。
- 抽出ルール: 電話番号が複数ある場合は本人の携帯・直通を優先しFAXは除外。郵便番号は住所に含める。ふりがなは扱いません。
- 形式チェック: メールアドレス・URLの形式が不正な場合はエラーで登録を止めます。
- **重複検知**: メール（なければ「企業＋氏名」）で既存名刺を検出。閲覧権限のある利用者には既存データと新規抽出の比較（差異を強調）を表示し、既存の更新か破棄を選択。権限のない利用者には内容を見せず「既に登録されています」とだけ表示して登録を止めます。更新できるのは登録者とadminのみで、登録者は元のまま保持します。
- 一覧: 氏名・会社名で検索（部分一致/完全一致、AND/OR選択、全半角・大小・空白差を吸収）、ソート（氏名/会社名/登録日）、ページング（20/50/100件）。
- 登録後の編集・削除: 登録者本人とadminのみ。
- 失敗時: 読み取り失敗・保存失敗は簡潔なメッセージで表示し、再試行できます（読み取り失敗時の手入力続行は不可）。詳細はサーバーログのみ。

## 動作確認
手順（手動）:
1. adminでログインし、利用者を2名追加・有効化する。
2. 名刺画像（JPEG/PNG/HEIC）を「名刺を登録」からアップロード → 抽出結果と元画像を確認・修正して登録。
3. 同じ名刺をもう一度登録して重複検知を確認。
4. 別の利用者で一覧・詳細・画像URL直打ちが404になることを確認 → adminで企業/部署/人物の許可を付与して見えることを確認 → 解除して見えなくなることを確認。

結果:
- **自動検証済み（Claude APIを使わず、抽出結果を架空データに差し替えて実施）**: ログイン/有効化/コード失効、画像変換と不正画像拒否、空欄警告、必須・形式チェック、重複検知（権限あり/なし）、権限制御（一覧・検索・詳細・画像・編集・削除、企業/部署/人物許可、解除後の残存、同名部署・同姓同名の非拡大）、ページング・ソート・検索、SQLインジェクション文字列。
- **未確認**: 実際のClaude APIでの名刺読み取り精度と、`CLAUDE_MODEL` の既定値がAPIキーで利用可能かの確認、実SMTPでの招待メール送信、評価当日の名刺画像での期待値照合。APIキー設定後に上記手順2で確認してください（個人情報保護のため、名刺画像と期待値はリポジトリに含めず、ローカルの `fixtures_private/`（gitignore済み）で管理する運用です）。

## 制約・未実装
- CSRF対策は未実装（Cookieは SameSite=Lax）。ログイン試行制限・パスワード再設定・セルフサインアップ・複数組織は対象外。
- 有効化コードに有効期限なし（1回使用・5回失敗で失効）。`SECRET_KEY` 未変更のままの運用は不可。
- 名刺の裏面・1枚に複数名刺が写る画像は考慮していません。SMTPは平文パスワード認証（STARTTLS）のみ。
